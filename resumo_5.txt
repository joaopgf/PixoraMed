3. ARQUITETURA ATUAL
--------------------
Navegador -> API principal (backend/, Render "pixoramed")
               login, histórico, decisão da classe, serve o site React
               -> HTTP + cabeçalho X-Token-IA -> Microsserviço de IA (ia/, Render
                  "pixoramed-ia"): carrega os .onnx uma vez, pré-processa, roda o
                  modelo e devolve só probabilidades. Não acessa banco, não guarda
                  imagem.
             -> Neon (PostgreSQL): usuarios, sessoes, treinos, previsoes.
Docker Compose local: db, backend, ia, frontend (nginx em localhost:8080).
A API principal não tem mais onnxruntime, opencv nem pillow nas dependências de
produção (ficaram em backend/requirements-dev.txt para os scripts de exportação).


4. LOGIN
--------
Arquivos: backend/app/autenticacao.py, routers/auth.py, tabelas.py, esquemas.py,
frontend/src/estado.tsx, api.ts, pages/Login.tsx.
- Rotas: POST /api/auth/cadastro (201; e-mail repetido 409), POST /api/auth/login
  (401 com a mesma mensagem para e-mail inexistente e senha errada), GET /api/auth/eu,
  POST /api/auth/sair (204).
- Senha: hashlib.scrypt (n=2**14, r=8, p=1, salt 16 bytes), formato
  scrypt$n$r$p$salt$hash. Conferência com hmac.compare_digest e HASH_FALSO para o
  tempo de resposta não revelar quem tem conta.
- Sessão: token secrets.token_urlsafe(32); o banco guarda só o SHA-256. Validade
  SESSAO_HORAS (padrão 8). Sair apaga a sessão no servidor.
- /api/previsoes (GET e POST) exige login; cada usuário vê só as próprias análises.
  /api/treinos e /api/modelos continuam públicas.
- Migração: atualizar_esquema() em app/db.py acrescenta previsoes.usuario_id quando
  falta (caso do Neon). As análises de teste antigas (PXM-000001 a 000003) ficaram
  sem dono e não aparecem para ninguém; podem ser apagadas pelo SQL Editor do Neon.
- Frontend: "Manter conectado" usa localStorage; sem a opção, sessionStorage.
  401 com token encerra a sessão e mostra "Sua sessão expirou. Entre novamente."
  Entrar e sair limpam o cache do TanStack Query.
- Sem MFA, recuperação de senha e limite de tentativas (trabalho futuro).
- Sem dependências novas: só biblioteca padrão.

- Testes do backend usam uma IA falsa (httpx.MockTransport, fixture ia_falsa em
  backend/tests/conftest.py). Testes de ia/ usam os 3 modelos reais de models/.

11. COMO RODAR
--------------
Docker, da raiz (app em localhost:8080; API em 8000/docs; IA em 8001/docs):
  docker compose up --build
Sem Docker, use o mesmo token nos dois serviços:
  cd ia
  set IA_TOKEN=token-local
  uvicorn app.main:app --reload --port 8001
  cd backend
  .venv\Scripts\activate
  set IA_TOKEN=token-local
  uvicorn app.main:app --reload
  cd frontend
  npm run dev
Testes:
  cd backend && pytest
  cd ia && pytest        (no PC, rodei com ..\backend\.venv\Scripts\python -m pytest)
Terraform, em infra/terraform (terraform.tfvars já preenchido pelo João):
  terraform plan      e só depois de o João aprovar: terraform apply
Workflows: cd docs\bpmn\gerador e python gerar.py
Para a banca: abrir o site e a página Nova análise uns 5 minutos antes.
