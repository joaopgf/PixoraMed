5. BACKEND (SPRING BOOT)
------------------------
Java 21, Spring Boot 4.1.2 (gerado no start.spring.io), Maven. Pacote com.pixoramed:
  controller (AuthController, PredictionController, TrainingController)
  service    (AuthService, PredictionService, DecisionService, TrainingService,
              AiServiceClient)
  repository (UserRepository, TrainingRepository, PredictionRepository)
  model      (User, Training, Prediction)  -> tabelas users, trainings, predictions
  dto        (records; AiModel/AiPrediction leem o snake_case da IA com @JsonAlias)
  security   (SecurityConfig: rotas públicas, JWT HS256 via oauth2-resource-server,
              BCrypt, CORS; TokenService gera o JWT com subject = id do usuário)
  exception  (ApiException + GlobalExceptionHandler -> {"message": "..."})
Rotas: POST /api/auth/register (201, 409 se e-mail existe), POST /api/auth/login
  (401 "E-mail ou senha incorretos." nos dois casos), GET /api/health, GET
  /api/trainings, GET /api/models (públicas); POST /api/predictions (multipart
  modelId + file) e GET /api/predictions?limit= (até 100) exigem Bearer token.
  Não há rota de logout nem /me (removidas por não serem usadas).
Configuração: application.properties só com ${VAR}; spring.config.import lê
  backend/.env. Obrigatórias: DATABASE_URL (JDBC), DATABASE_USERNAME,
  DATABASE_PASSWORD, JWT_SECRET (>= 32 caracteres, senão não sobe),
  CORS_ALLOWED_ORIGINS, AI_SERVICE_URL, AI_SERVICE_TOKEN. Opcionais:
  JWT_EXPIRATION_HOURS (8), AI_SERVICE_TIMEOUT_SECONDS (120), INCONCLUSIVE_THRESHOLD
  (0.8), IMPORT_TRAININGS_ON_STARTUP (true), PORT (8080).
Dados: src/main/resources/data/training-results.csv (antigo data/resultados.csv, 29
  linhas, ";" e vírgula decimal, cabeçalho em português vindo dos notebooks).
  TrainingService importa no ApplicationReadyEvent, idempotente (chave runAt+dataset).
  Nomes PT viram ids: Pele->skin, Oral->oral, Cérebro->brain; cor->color,
  cinza->gray. Outros cânceres (Rim etc.) ficam no banco mas o site filtra.
AiServiceClient: RestClient, cache de modelos 5 min, timeout 120 s. 404/413/422 da IA
  voltam para a tela; o resto vira 503 "O serviço de IA está indisponível...".
Dockerfile multi-stage (maven:3.9-eclipse-temurin-21 -> eclipse-temurin:21-jre-alpine),

10. MODELOS E COMO CADA MÓDULO DECIDE
-------------------------------------
Pele (skin_color): ensemble de 5 EfficientNet-B0 calibradas (Platt), um ONNX de ~80 MB.
  RGB 224x224, resize bicúbico PIL, /255 e normalização ImageNet, mínimo 100 px.
  Classes benign e malignant (mel + bcc); akiec fora do treino. Limiar ~0,18: vira
  malignant mesmo abaixo de 50%. Sem inconclusivo; abaixo de 80% em ambas, mantém a
  classe e a tela mostra "baixa certeza".
Oral (oral_color): CNN pequena (~24 mil parâmetros), RGB 128x128, /255. normal, scc.
Cérebro (brain_gray): CNN pequena, cinza 128x128, sem divisão. glioma, menin, tumor
  (tela: hipofisário). Não detecta ausência de tumor.
Oral e Cérebro: "inconclusive" abaixo de 80% (INCONCLUSIVE_THRESHOLD).
OpenCV lê em BGR e o sistema converte para RGB. BGR ou tirar /255 derruba o Oral de
  96,5% para ~52%. Modelo treinado em RGB.
CNN dos notebooks: 3 blocos Conv-ReLU-MaxPool (16/32/64), AdaptiveAvgPool, Dropout
  0,25, Linear; Adam lr 0,001, batch 64, 450 épocas, StratifiedKFold 5, seed 42.
Código original da Pele indisponível (PC do colega desligou). Arquivos .pt originais
  da Pele (HAM10000_PACOTE_INFERENCIA) e alguns zips não foram encontrados em 06/11:
  o skin_color.onnx no GitHub é a cópia segura.

14. COMO RODAR
--------------
Tudo local com Docker (dentro de infra/):
  copy .env.example .env      (já existe um .env local)
  docker compose up --build   -> site http://localhost:5173, API :8080/api/health
  docker compose down         (sem -v; -v apaga o banco local)
Sem Docker:
  backend:    mvn spring-boot:run   (precisa de backend/.env e de um Postgres; pode ser
              "docker compose up db" em infra/)
  ai-service: python -m venv .venv; pip install -r requirements.txt; .env com
              AI_SERVICE_TOKEN; uvicorn app.main:app --reload --port 8001
  frontend:   npm ci; npm run dev
Testes: backend "mvn test"; ai-service "pytest" (Python do PC é 3.14; testei em Docker
  python:3.12-slim); frontend "npm run build".
Terraform (infra/terraform): terraform plan; apply só com aprovação do João.
BPMN: cd docs\bpmn\generator; python generate.py; exportar PNG (bpmn.io ou bpmn-js).
Deck: python-pptx instalado no Python do sistema nesta sessão; LibreOffice NÃO existe;
  PowerPoint existe e exporta slides via COM (PowerPoint.Application, Slide.Export).
Banca: abrir o site ~5 min antes para acordar backend e IA.


15. ARMADILHAS ENCONTRADAS
--------------------------
- Render gratuito: atualizar serviço pelo Terraform falha (modo de manutenção). Use
  env groups e a API/painel do Render. Variável do serviço tem prioridade sobre a do
  env group.
- Provider Vercel 5.26.1: "Unexpected Identity Change" após criar o projeto; resolver
  com state rm + import.
- Render dorme após 15 min; primeira chamada pode levar ~1 min.
- Spring Boot 4 usa Jackson 3, mas as anotações (@JsonAlias) seguem em
  com.fasterxml.jackson.annotation. Starter web agora é spring-boot-starter-webmvc.
- Vite no compose (Windows): precisa CHOKIDAR_USEPOLLING=true para ver mudanças.
- OneDrive trava pastas: git mv de pasta deu "Permission denied" (mover arquivo por
  arquivo) e rm de pasta em uso deu "Device or resource busy".
- Checagem de segurança bloqueia rm/rmdir com glob ou caminho relativo depois de cd;
  use caminho absoluto completo.
- Git Bash + Python do Windows: /c/... vira C:\c\...; passe caminhos C:/... ao Python
  (foi assim que surgiu a pasta C:\c).
- Console do Windows (cp1252) quebra print com caracteres como "→": use
  PYTHONIOENCODING=utf-8.
- Validador de XSD da skill pptx não roda neste Windows (falha igual no deck original);
  confira abrindo no PowerPoint.
- Vercel: o rewrite externo faz cache por padrão em projetos novos; está desligado
  em /api no vercel.json.
- Terraform: executável em %LOCALAPPDATA%\Microsoft\WinGet\Packages\
  Hashicorp.Terraform_Microsoft.Winget.Source_8wekyb3d8bbwe\terraform.exe; o PATH
  também aponta para uma pasta antiga do Desktop.
- *.tfplan guarda segredos (no .gitignore); terraform.tfstate não pode ser perdido.
- Porta 8000/8080: o Docker do João pode estar rodando; confira antes de escrever no
  banco. Não rodar "down -v" no projeto principal.
- npm 11: aviso "allow-scripts" no esbuild; o build funciona.
